2  控制流、结构体、模块与类型系统

在上一章里，我们盘点了 Zig 的很多语法特性，尤其是在 Section 1.2.2 和 Section 1.2.3 中解析了项目的基础骨架。 但要应付日常开发，我们还有几个重量级的核心机制必须吃透。

在本章中，我们将从日常写业务最常用的控制流语句（如各种循环、条件分支等）讲起； 接着聊聊 Zig 里的结构体（Struct），以及如何在 Zig 里用结构体优雅实现面向对象（OOP）模式； 随后我们会深入类型系统的类型推断与类型转换（Type Casting）； 最后，我们会揭开 Zig 模块（Module）的神秘面纱——看看为什么在 Zig 里“模块本质上就是一个大结构体”。

2.1 控制流（Control Flow）

写程序本质上就是做逻辑决断：要么满足某种条件就走这段逻辑，要么对一批数据做循环迭代。 在计算机科学中，“控制流”指的就是程序指令的执行顺序。而能够改变执行顺序的语法骨架，我们就叫它控制流语句。

大家最熟悉的控制流包括 if/else、switch、for/while 循环，以及随时用来跳出或继续的 break 和 continue。

2.1.1 if / else 条件分支

条件分支允许我们根据布尔表达式的真假，决定执行哪一段代码块。 在 Zig 里写 if/else 非常直观，跟大多数 C 族语言一脉相承：if 后面跟带括号的布尔表达式，大括号内是命中 true 时执行的逻辑；可选的 else 块则在表达式为 false 时兜底。

来看个简单的例子：

const x = 5;
if (x > 10) {
    try stdout.print("x > 10!\n", .{});
} else {
    try stdout.print("x <= 10!\n", .{});
}
try stdout.flush();
x <= 10!

2.1.2 switch 分支匹配

Zig 也提供了非常强大的 switch 语句，整体风格和 Rust 的模式匹配颇为神似。 用法是用 switch (value) { ... } 包住需要做分支判断的值，在大括号里罗列各个匹配分支。

看下面这个例子：我们定义了一个叫 Role 的枚举（关于枚举的细节详见 Section 7.6），列举了一家假想公司里的各路技术与业务岗位（如软件工程师 SE、数据工程师 DE、产品经理 PM 等）。

在 switch 中，我们用到了 Zig 的类型推断（分支名前面的小圆点 .，详见 Section 2.4），这样编译器就能自动推导出来自 Role 的具体分支。 同时，多个匹配项可以用逗号合并到同一个分支中（比如 .DE, .DA => ...）：

const std = @import("std");
const Role = enum {
    SE, DPE, DE, DA, PM, PO, KS
};

pub fn main(init: std.process.Init) !void {
    var stdout_buffer: [1024]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &stdout_buffer);
    const stdout = &stdout_writer.interface;
    var area: []const u8 = undefined;
    const role = Role.SE;
    switch (role) {
        .PM, .SE, .DPE, .PO => {
            area = "Platform";
        },
        .DE, .DA => {
            area = "Data & Analytics";
        },
        .KS => {
            area = "Sales";
        },
    }
    try stdout.print("{s}\n", .{area});
    try stdout.flush();
}
Platform

2.1.2.1 switch 必须穷尽所有可能（Exhaustive）

这里有一个非常硬核的设计约束：在 Zig 里，switch 语句必须穷尽（Exhaust）目标类型的所有可能取值！

在上面的例子中，role 变量属于 Role 枚举类型，它一共只有 7 种可能取值。你在 switch 里就必须保证这 7 种情况都被明确覆盖，一个都不能漏。 如果你少写了一个分支，编译器会立刻撂挑子报错，绝不允许留下任何未被显式处理的漏网之鱼。这和 Rust 的 match 机制如出一辙，最大程度规避了逻辑死角。

2.1.2.2 兜底分支 else

如果取值范围太大（比如整数或字符），不可能手动把每一个值都列出来，这时候就可以祭出 else 兜底分支。

看看 Zig 标准库 debug.zig 模块1 中的这个代码片段：

pub fn dump_hex_fallible(bytes: []const u8) !void {
    // 省略部分代码...
    switch (byte) {
        '\n' => try writer.writeAll("␊"),
        '\r' => try writer.writeAll("␍"),
        '\t' => try writer.writeAll("␉"),
        else => try writer.writeByte('.'),
    }
}

在实际业务中，else 分支也常被用来处理“不支持的非法状态”，直接返回错误，或者调用 @panic() 终止程序：

另外请注意：Zig 的 switch 是一个表达式（Expression）！这意味着分支执行的结果可以直接赋给一个新对象：

const level: u8 = 4;
const category = switch (level) {
    1, 2 => "beginner",
    3 => "professional",
    else => {
        @panic("Not supported level!");
    },
};
try stdout.print("{s}\n", .{category});
try stdout.flush();
thread 13103 panic: Not supported level!
t.zig:9:13: 0x1033c58 in main (switch2)
            @panic("Not supported level!");
            ^

2.1.2.3 在 switch 中支持范围表达式

Zig 的 switch 还支持用 ... 操作符定义闭区间范围（两端均包含）：

const level: u8 = 4;
const category = switch (level) {
    0...25 => "beginner",
    26...75 => "intermediary",
    76...100 => "professional",
    else => {
        @panic("Not supported level!");
    },
};
try stdout.print("{s}\n", .{category});
try stdout.flush();
beginner

字符匹配也同样好使，比如 'a'...'z' 就能瞬间匹配所有小写英文字母。

2.1.2.4 带标签的 switch 语句（Labeled switch）

在 Section 1.7 中我们介绍过如何为代码块添加标签并配合 break 使用。从 Zig 0.14.0 开始，你也可以为 switch 语句显式指定一个标签（Labeled switch）。结合 continue :label value;，你可以让执行流回到 switch 语句的开头，跳转到匹配的另一个分支继续执行，这样几乎可以实现类似 C 语言 goto 的模式。在下面的例子中，执行流两次回到 switch 语句的开头，最后停在 3 这个分支：

xsw: switch (@as(u8, 1)) {
    1 => {
        try stdout.print("First branch\n", .{});
        continue :xsw 2;
    },
    2 => continue :xsw 3,
    3 => return,
    4 => {},
    else => {
        try stdout.print(
            "Unmatched case, value: {d}\n", .{@as(u8, 1)}
        );
        try stdout.flush();
    },
}
First branch

2.1.3 延迟执行：defer 关键字

在 Zig 的控制流与内存管理中，defer 拥有举足轻重的地位。 简单一句话概括：defer 允许你登记一条表达式，让它在退出当前作用域时自动执行。

回顾我们在 Section 1.7 中所讨论的内容，Zig 中凡是用一对花括号（{}）界定的结构（函数体、for/while 循环、if/else 语句等）都拥有各自独立的作用域。 Go 语言开发者可能马上会想到 Go 里的 defer。 但请务必注意区别：Go 的 defer 是在当前“函数退出”时执行，而 Zig 的 defer 是在当前“作用域退出”时执行！ 一个函数内部可以有循环、if 块等很多子作用域，一旦跳出该大括号，挂在里面的 defer 就会立刻触发，心智模型更紧凑、资源回收也更及时。

看个最直观的例子：

const std = @import("std");
pub fn main() !void {
    defer std.debug.print(
        "Exiting function ...\n", .{}
    );
    std.debug.print("Adding some numbers ...\n", .{});
    const x = 2 + 2; _ = x;
    std.debug.print("Multiplying ...\n", .{});
    const y = 2 * 8; _ = y;
}
Adding some numbers ...
Multiplying ...
Exiting function ...

需要指出的是：defer 属于无条件延迟（Unconditional defer）。 不管你是正常 return 退出、遇到报错提前退出、还是被 break 跳出，只要出了这个花括号作用域，defer 登记的动作就必定执行，雷打不动。

2.1.4 报错才触发的容错清理：errdefer

有了无条件的 defer，Zig 还贴心准备了它的同胞兄弟——errdefer。 errdefer 是有条件的延迟执行（Conditional defer）：它登记的表达式，只有在当前作用域因发生错误而提前退出时才会执行！ 如果整个流程顺顺当当跑完退出，errdefer 里的内容就像空气一样，完全不会被调用。

这在系统底层开发中简直是神技！比如你向系统连续申请了 3 块内存或打开了 3 个资源句柄，当第 3 个操作报错失败时，你必须把前面已经申请成功的 2 个半成品资源及时释放掉。用 errdefer 就能写出清晰的出错清理逻辑（我们会在 Section 10.2.4 做更多实战演示）。

另外还要记住一个关键执行顺序规则：多个 defer / errdefer 是按后进先出（LIFO）的倒序执行的！（即写在后面的先执行，写在前面的后执行）。

看下面这段代码验证：

const std = @import("std");
fn foo() !void { return error.FooError; }
pub fn main() !void {
    var i: usize = 1;
    errdefer std.debug.print("Value of i: {d}\n", .{i});
    defer i = 2;
    try foo();
}
Value of i: 2
error: FooError
/t.zig:6:5: 0x1037e48 in foo (defer)
    return error.FooError;
    ^

因为 defer i = 2; 写在后面，所以在报错退出时它先执行，把 i 改成了 2；随后前面的 errdefer 打印出的就是 2。 如果调换两行顺序：

const std = @import("std");
fn foo() !void { return error.FooError; }
pub fn main() !void {
    var i: usize = 1;
    defer i = 2;
    errdefer std.debug.print("Value of i: {d}\n", .{i});
    try foo();
}
Value of i: 1
error: FooError
/t.zig:6:5: 0x1037e48 in foo (defer)
    return error.FooError;
    ^

2.1.5 for 循环迭代

日常处理数组或切片，for 循环是绝对的主力。 Zig 的 for 语法有自己的独特审美：用括号包住要迭代的集合，后面用一对竖线 |val| 声明接收每个元素的迭代器变量：

for (items) |value| {
    // 循环体代码
}

看个遍历数组打印 ASCII 码的例子：

const name = [_]u8{'P','e','d','r','o'};
for (name) |char| {
    try stdout.print("{d} | ", .{char});
}
try stdout.flush();
80 | 101 | 100 | 114 | 111 |

如果遍历时既想要元素值，又想要当前下标索引怎么办？ 非常优雅！Zig 允许在 for 括号里传入第二个范围序列 0..，并在竖线里同时捕获值与下标：

const name = "Pedro";
for (name, 0..) |_, i| {
    try stdout.print("{d} | ", .{i});
}
try stdout.flush();
0 | 1 | 2 | 3 | 4 |

注意上面我们用 _ 显式丢弃了字符值，只保留了索引计数器 i，因为正如我们在 Section 1.4 中强调的，Zig 中声明的每一个对象都必须被使用。

2.1.6 while 循环与自增表达式

while 负责按条件循环，只要括号里的布尔表达式为 true 就一直跑：

var i: u8 = 1;
while (i < 5) {
    try stdout.print("{d} | ", .{i});
    i += 1;
}
try stdout.flush();
1 | 2 | 3 | 4 |

Zig 还支持在 while 头部通过冒号 : (expr) 绑定自增步进逻辑，写起来非常紧凑：

var i: u8 = 1;
while (i < 5) : (i += 1) {
    try stdout.print("{d} | ", .{i});
}
try stdout.flush();
1 | 2 | 3 | 4 |

2.1.7 掌控节奏：break 与 continue

想中途跳出循环用 break，想跳过当前轮次直奔下一轮用 continue。

看这个用 break 终止无限循环的例子：

var i: usize = 0;
while (true) {
    if (i == 10) {
        break;
    }
    i += 1;
}
try std.testing.expect(i == 10);
try stdout.print("Everything worked!", .{});
try stdout.flush();
Everything worked!

以及用 continue 过滤偶数、只打印奇数的经典用法：

const ns = [_]u8{1,2,3,4,5,6};
for (ns) |i| {
    if ((i % 2) == 0) {
        continue;
    }
    try stdout.print("{d} | ", .{i});
}
try stdout.flush();
1 | 3 | 5 |

2.2 函数入参是不可变的！

这里必须郑重强调 Zig 的另一条铁律：在 Zig 里，函数的所有形参默认全都是不可变常量（Immutable）！

看看下面这个反例：在 add2 函数里试图对传进来的参数 x 做直接修改，编译器会立即报错：

const std = @import("std");
fn add2(x: u32) u32 {
    x = x + 2;
    return x;
}

pub fn main() !void {
    const y = add2(4);
    std.debug.print("{d}\n", .{y});
}
t.zig:3:5: error: cannot assign to constant
    x = x + 2;
    ^

2.2.1 免费的编译器底层优化

Zig 为什么要对函数参数做如此苛刻的不可变约束？ 因为这样给编译器开辟了巨大的性能优化空间！

如果函数参数属于我们在 Section 1.5 中列举的基础数据类型（如 u32、bool），这个对象总是按值传给函数，也就是说，它会被拷贝到函数的栈帧中。 但如果输入对象的数据类型更复杂，比如结构体实例、数组或联合体值等，zig 编译器就会替你决定哪种策略最好：要么按值传递，要么按引用传递。编译器总会选择对你来说更快的策略。之所以能免费获得这种优化，正是因为 Zig 中的函数参数是不可变的。

2.2.2 确实想改入参？传指针！

如果在业务场景下确实需要由函数修改外部状态（比如调用 C 接口或更新复杂结构体），正规解法是传指针（例如用 *u32 代替 u32），然后在函数体里通过 .* 做解引用修改：

const std = @import("std");
fn add2(x: *u32) void {
    const d: u32 = 2;
    x.* = x.* + d;
}

pub fn main() !void {
    var x: u32 = 4;
    add2(&x);
    std.debug.print("Result: {d}\n", .{x});
}
Result: 6

2.3 结构体与面向对象（Structs and OOP）

Zig 更偏向于 C 风格的过程式语言，而不是 C++ 或 Java 那套重型面向对象。所以 Zig 中没有类、接口或类继承这类高级面向对象编程模式。不过，在 Zig 中仍然可以通过结构体定义实现面向对象编程。 但别慌！在 Zig 里，我们完全可以通过结构体（Struct）写出非常纯粹地道的面向对象代码。

你可以用 struct 定义新类型，不仅可以包含字段成员（Data members），还可以在里面挂载函数（Methods）。这样属于该类型的所有实例就能直接调用这些方法。

在命名上，有一个贯穿整个 Zig 标准库的惯例： - init()：充当构造函数，用于创建和初始化实例； - deinit()：充当析构函数，负责释放该实例占用的底层资源。

看下面这个经典的 User 结构体：

const std = @import("std");
const User = struct {
    id: u64,
    name: []const u8,
    email: []const u8,

    fn init(id: u64,
            name: []const u8,
            email: []const u8) User {

        return User {
            .id = id,
            .name = name,
            .email = email
        };
    }

    fn print_name(self: User, stdout: *std.Io.Writer) !void {
        try stdout.print("{s}\n", .{self.name});
        try stdout.flush();
    }
};

pub fn main(init: std.process.Init) !void {
    var stdout_buffer: [1024]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &stdout_buffer);
    const stdout = &stdout_writer.interface;
    const u = User.init(1, "pedro", "email@gmail.com");
    try u.print_name(stdout);
}
pedro

注意细节：结构体内部每个字段定义末尾必须以逗号（,）结尾，而不是分号。

2.3.1 跨模块可见性：pub 关键字

pub 关键字是“public（公开）”的缩写，用来将模块内的结构体、函数或对象暴露给外部模块使用。如果某个声明没有加 pub，它就只能在定义它的当前模块内部被访问。

以刚才的 User 结构体为例：假设它声明在 user.zig 模块中且未加 pub，而在另一个 register.zig 模块中导入并使用 user.User，编译器会报错提示 'User' is not marked 'pub'：

// register.zig
const user = @import("user.zig");
pub fn main() !void {
    const u: user.User = undefined;
    _ = u;
}
register.zig:3:18: error: 'User' is not marked 'pub'
    const u: user.User = undefined;
             ~~~~^~~~~
user.zig:3:1: note: declared here
const User = struct {
^~~~~

回到 user.zig 给 User 加上 pub 后，类型本身就可以跨模块引用了：

// user.zig
// Added the `pub` keyword to `User`
pub const User = struct {
// ...
// register.zig
// This works fine now!
const user = @import("user.zig");
pub fn main() !void {
    const u: user.User = undefined;
    _ = u;
}

但请注意：给结构体本身加 pub，并不会自动把结构体内部的方法也变成公开的！ 如果此时在 register.zig 中调用 user.User.init(...)，编译器依然会报错提示 'init' is not marked 'pub'：

const user = @import("user.zig");
pub fn main() !void {
    const u: user.User = user.User.init(
        1, "pedro", "email@gmail.com"
    );
    _ = u;
}
register.zig:3:35: error: 'init' is not marked 'pub'
    const u: user.User = user.User.init(
                         ~~~~~~~~~^~~~~
user.zig:8:5: note: declared here
    fn init(id: u64,
    ^~~~~~~

因此，只有把 User 结构体本身以及需要跨模块调用的 init()、print_name() 方法都加上 pub 标记，外部模块才能完整调用：

// user.zig
// Added the `pub` keyword to `User.init`
    pub fn init(
// ...
// Added the `pub` keyword to `User.print_name`
    pub fn print_name(self: User) !void {
// ...
// register.zig
// This works fine now!
const user = @import("user.zig");
pub fn main() !void {
    const u: user.User = user.User.init(
        1, "pedro", "email@gmail.com"
    );
    _ = u;
}

2.3.2 匿名结构体字面量（Anonymous Struct Literals）

正常声明结构体字面量时，一般会在大括号前带上类型名 User { ... }。

const eu = User {
    .id = 1,
    .name = "Pedro",
    .email = "someemail@gmail.com"
};
_ = eu;

但在 Zig 中，你可以直接省掉类型名，用 .{} 这种匿名结构体字面量语法！

前面的小圆点 . 会告诉编译器：“这里有个结构体，麻烦结合上下文帮我自动推导它的类型！”

我们在 stdout.print() 里传参数时见到的 .{ "world" }，就是典型的匿名结构体字面量。这里通常使用匿名结构体字面量，让 zig 编译器替你确定这个匿名结构体的类型：

const std = @import("std");
pub fn main(init: std.process.Init) !void {
    var stdout_buffer: [1024]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &stdout_buffer);
    const stdout = &stdout_writer.interface;
    try stdout.print("Hello, {s}!\n", .{"world"});
    try stdout.flush();
}
Hello, world!

2.3.3 结构体类型必须是常量（const）

在 Zig 中，声明新的结构体类型时必须使用 const 关键字。换言之，所有类型声明在编译期都必须是常量（const）或编译期已知（comptime，详见 Section 12.1）。你不能使用 var 关键字去声明一个结构体类型。在下面的 Vec3 例子中，这个声明是允许的，因为我用 const 关键字声明了这个新的数据类型：

const Vec3 = struct {
    x: f64,
    y: f64,
    z: f64,
};

2.3.4 结构体方法的 self 参数

在方法定义中，我们通常用 self 作为第一个形参，它代表当前调用该方法的对象实例本身。

看下面这个三维向量 Vec3 计算欧氏距离的示例：

const std = @import("std");
const m = std.math;
const Vec3 = struct {
    x: f64,
    y: f64,
    z: f64,

    pub fn distance(self: Vec3, other: Vec3) f64 {
        const xd = m.pow(f64, self.x - other.x, 2.0);
        const yd = m.pow(f64, self.y - other.y, 2.0);
        const zd = m.pow(f64, self.z - other.z, 2.0);
        return m.sqrt(xd + yd + zd);
    }
};

调用时直接 v1.distance(v2)，Zig 会自动把 v1 作为 self 传进去：

const v1 = Vec3 {
    .x = 4.2, .y = 2.4, .z = 0.9
};
const v2 = Vec3 {
    .x = 5.1, .y = 5.6, .z = 1.6
};

std.debug.print(
    "Distance: {d}\n",
    .{v1.distance(v2)}
);
Distance: 3.3970575502926055

2.3.5 结构体内部状态变更：*Self vs Self

正如在 Section 2.3.4 中所述，结构体方法中的 self 参数代表调用该方法的结构体实例本身。如果一个方法只读取数据、不改动任何字段（如上面的 distance()），形参写 self: Vec3 就够了。

但如果你的方法需要修改结构体自身的字段（例如给坐标翻倍），该怎么写？

还记得前文讲过的“函数入参是不可变常量”吗？如果你写 self: Vec3 然后去执行 self.x *= 2.0;，编译器马上会怒喷 cannot assign to constant！

因此，只要方法内部需要修改自身状态，self 参数必须声明为指针类型 *Vec3！

const std = @import("std");
const m = std.math;
const Vec3 = struct {
    x: f64,
    y: f64,
    z: f64,

    pub fn distance(self: Vec3, other: Vec3) f64 {
        const xd = m.pow(f64, self.x - other.x, 2.0);
        const yd = m.pow(f64, self.y - other.y, 2.0);
        const zd = m.pow(f64, self.z - other.z, 2.0);
        return m.sqrt(xd + yd + zd);
    }

    pub fn twice(self: *Vec3) void {
        self.x = self.x * 2.0;
        self.y = self.y * 2.0;
        self.z = self.z * 2.0;
    }
};

调用也非常省心：哪怕调用方写的是 v3.twice()，Zig 也会自动为我们取指针传递，直接原地更新：

var v3 = Vec3 {
    .x = 4.2, .y = 2.4, .z = 0.9
};
v3.twice();
std.debug.print("Doubled: {d}\n", .{v3.x});
Doubled: 8.4

反过来，如果把 twice() 的参数签名写成按值接收 self: Vec3，由于 Zig 中所有函数形参默认都是不可变常量（见 Section 2.2），尝试修改 self.x 就会触发如下编译错误：

// 如果将函数签名改为按值接收：
    pub fn twice(self: Vec3) void {
t.zig:16:13: error: cannot assign to constant
        self.x = self.x * 2.0;
        ~~~~^~
Note

注意事项：只要结构体的方法需要修改自身任何一个字段的值，函数签名里的 self 务必写成指针类型 *T，而不是普通值 T。

2.4 类型推断（Type Inference）

虽然 Zig 是严格的强类型语言，但它并不死板。很多时候我们不需要把冗长的类型名反反复复手敲一遍。 在 Zig 中，触发类型推断的魔术符号就是小圆点（.）。

每当你看到以 . 开头的字面量或枚举项时，就代表我们在请编译器结合上下文自动推断该表达式的类型。我们在 Section 2.3.2 中介绍匿名结构体字面量，以及在 Section 2.1.2 中介绍 switch 分支匹配枚举值时，都已经见过这种类型推断的用法。

再看一个例子：下面这个 fence() 函数摘自 Zig 标准库的 atomic.zig 模块2（译注：在 Zig 0.17.1 的标准库中，atomic.zig 已不再包含这个函数，这里仅作为类型推断的示例）。函数里有很多我们还没讲到的东西，比如 comptime、inline、extern 是什么意思。先忽略它们，只关注函数内部的 switch 语句。

pub inline fn fence(self: *Self, comptime order: AtomicOrder) void {
    // many lines of code ...
    if (builtin.sanitize_thread) {
        const tsan = struct {
            extern "c" fn __tsan_acquire(addr: *anyopaque) void;
            extern "c" fn __tsan_release(addr: *anyopaque) void;
        };

        const addr: *anyopaque = self;
        return switch (order) {
            .unordered, .monotonic => @compileError(
                @tagName(order)
                ++ " only applies to atomic loads and stores"
            ),
            .acquire => tsan.__tsan_acquire(addr),
            .release => tsan.__tsan_release(addr),
            .acq_rel, .seq_cst => {
                tsan.__tsan_acquire(addr);
                tsan.__tsan_release(addr);
            },
        };
    }
    return @fence(order);
}

这个 switch 语句以 order 对象作为输入。从类型注解可以看出，order 是 fence() 的参数之一，类型为 AtomicOrder。switch 里有一批以点号开头的值，比如 .release 和 .acquire。由于这些值前面带点号，我们是在请 zig 编译器推断它们的类型：编译器会查看 switch 的输入对象 order 的类型，即 AtomicOrder，从而推断出这些值是 AtomicOrder 的成员。

如果不用点号，就必须显式写出每个值的类型，比如把 .release 写成 AtomicOrder.release，而且 switch 里的每个值都得这样写，工作量很大。这就是 Zig 在 switch 语句中普遍使用类型推断的原因。

2.5 类型转换（Type Casting）

在底层开发中，不同位宽整型、浮点型或指针之间的类型互转是高频操作。 在 C 语言里常用 (int)x 强制转换，容易隐蔽地截断数据；而 Zig 提供了非常严谨的类型转换内置函数族。

当类型转换明确、无歧义且安全时，首选使用内置函数 @as(TargetType, value)（第一个参数为目标类型，第二个参数为待转换的对象）：

const std = @import("std");
const expect = std.testing.expect;
test {
    const x: usize = 500;
    const y = @as(u32, x);
    try expect(@TypeOf(y) == u32);
}
1/1 file6f2840a7682.test_0...OK
All 1 tests passed.

如果需要在不同类别的数据类型之间转换（例如将整数转换为浮点数，或将浮点数转换为整数），由于涉及数值表示方式的改变，Zig 要求使用表意明确的专用内置函数（如 @floatFromInt() 与 @intFromFloat()）：

const std = @import("std");
const expect = std.testing.expect;
test {
    const x: usize = 565;
    const y: f32 = @floatFromInt(x);
    try expect(@TypeOf(y) == f32);
}
1/1 file6f286a8a661b.test_0...OK
All 1 tests passed.

而对于指针对象（详见 Chapter 6），由于其存储的是内存地址，指针类型之间的转换需要使用专门的内置函数 @ptrCast()：

const std = @import("std");
const expect = std.testing.expect;
test {
    const bytes align(@alignOf(u32)) = [_]u8{
        0x12, 0x12, 0x12, 0x12
    };
    const u32_ptr: *const u32 = @ptrCast(&bytes);
    try expect(@TypeOf(u32_ptr) == *const u32);
}
1/1 file6f28631928f9.test_0...OK
All 1 tests passed.

2.6 模块的本质就是结构体

最后，揭晓一个在 Zig 里极其迷人且统一的概念：每一个 .zig 源码文件（即模块），在编译器内部其实就是一个结构体（Struct）！

当我们在代码里敲下：

const std = @import("std");

本质上，@import 是把整个标准库解析成了一个巨大的结构体对象，并赋给了 std 常量。我们用 std.debug.print 调用函数，跟访问普通结构体的静态方法在语法机制上没有任何区别。

看知名开源项目 zap 中的 thread_pool.zig3： 在这个文件里，作者在最外层直接定义了公开的 init() 方法，整个 .zig 文件就扮演了线程池结构体本身：

const std = @import("std");
const ThreadPool = @import("thread_pool.zig");
const num_cpus = std.Thread.getCpuCount()
    catch @panic("failed to get cpu core count");
const num_threads = std.math.cast(u16, num_cpus)
    catch std.math.maxInt(u16);
const pool = ThreadPool.init(
    .{ .max_threads = num_threads }
);

这个模块就像是一个大结构体：模块中所有的顶层函数都是这个结构体的方法，所有的顶层对象和结构体声明都是这个结构体的数据成员。模块本身就是这个结构体。
