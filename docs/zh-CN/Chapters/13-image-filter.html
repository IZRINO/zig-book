15  实战项目 4：开发图像灰度滤镜

在这章中，咱们来搞第四个趣味与硬核兼备的实战项目：开发一个给图片加滤镜的程序。 具体来说，我们要亲手实现一个灰度滤镜（Grayscale Filter），把任意一张彩色照片变成极具质感的黑白复古大片。

作为试验素材，我们使用智利裔美国知名演员 Pedro Pascal（佩德罗·帕斯卡）的照片（见 Figure 15.1）：

代码量其实并不大，但在动手敲代码之前，我们得先把数字图像的底层原理摸透：电脑到底是怎么在显卡和内存里用二进制表示颜色的？PNG（便携式网络图形）文件格式的内部又是怎么封装的？

本章跑通后，程序会吃进原始彩色 PNG 图片，并在当前工作目录吐出一张完全灰度化的黑白版本（如 Figure 15.2 所示）。 本项目的完整整合代码可以在官方仓库的 ZigExamples/image_filter 目录1找到。

15.1 人眼究竟是如何感知颜色的？

聊计算机图形学，必须先聊聊人眼的生理构造。因为数字图像背后的技术在很大程度上借鉴了人眼的工作方式。

你可以把人眼看成一个高精度的光学传感器： 我们看到的五彩斑斓，本质上都是物体表面对入射光线的反射。光是所有色彩的物理源头！ 正如艾萨克·牛顿在 1660 年代著名的三棱镜分光实验中所证实的2：白光其实是由各种单色光混合而成的。

而在人类视网膜里，分布着感知颜色的功臣——视锥细胞（Cone cells）。 人眼一共有 3 种不同的视锥细胞，它们分别对红（Red）、绿（Green）、蓝（Blue）三个波段的光谱最为敏感。

视锥细胞捕获到不同比例的红绿蓝光强后，转换成微弱的电信号顺着视神经传给大脑皮层。大脑将这三路电信号融合，最终在我们的脑海里呈现出千变万化的色彩世界！

15.2 计算机数字图像底层原理

在计算机图形学中，图像主要分为矢量图（Vector）和位图（光栅图 Raster）。我们日常处理的照片绝大多数都是位图（Raster Images）（如 JPEG、PNG）。

位图在本质上就是一个由像素点整齐排布构成的 2D 像素矩阵。 如 Figure 15.3 所示，把任何一张位图无限放大，你会看到一个个排列整齐的单色小方块——这就是像素（Pixel）：

像素越多，画面越细腻。常见的 1080P 高清图片分辨率是 \(1920 \times 1080\)，意味着整张图包含了高达 \(2,073,600\) 个像素点！

在主流的 RGB 颜色空间中，每个像素用三个数字 (R, G, B) 分别标明红、绿、蓝的亮度比例。比如 (199, 78, 70) 偏砖红，(129, 77, 250) 偏亮紫。

15.2.1 像素的排布与扫描方向

现代计算机屏幕和位图文件遵循标准的从上到下、从左到右的扫描线排布顺序： 矩阵的第 0 行从左往右排布，接着是第 1 行、第 2 行……如图 Figure 15.4 所示：

15.2.2 在代码中如何表示像素矩阵？

我们已经知道，光栅图像表示为二维像素矩阵。但 Zig 中并没有二维矩阵这个概念。实际上，大多数低级语言（Zig、C、Rust 等）都没有这个概念。那么，在 Zig 或其他低级语言中，怎样表示这样的像素矩阵呢？在这种情况下，大多数程序员选择的策略是直接用一个普通的一维数组来存储这个二维矩阵的值。换句话说，就是创建一个普通的一维数组，把两个维度上的所有值都存进这个一维数组。

之所以用无符号 8 位整数（u8）而不是其他整数类型来表示每种颜色的量，是因为它们占用的空间（即位数）尽可能少，这有助于减小图像（即二维矩阵）的二进制体积。同时，尽管它们能表示的”颜色量”范围相对较小（0 到 255），却能传达相当多的颜色精度和细节。 例如，假设有一张尺寸为 \(4 \times 3\) 的微型 RGB 图像（共 12 个像素，每个像素由 3 个 u8 整数表示，共计 \(3 \times 12 = 36\) 个整数），我们可以用如下包含 36 个 u8 元素的一维数组 matrix 来存储它：

const matrix = [_]u8{
    201, 10, 25, 185, 65, 70,
    65, 120, 110, 65, 120, 117,
    98, 95, 12, 213, 26, 88,
    143, 112, 65, 97, 99, 205,
    234, 105, 56, 43, 44, 216,
    45, 59, 243, 211, 209, 54,
};

对于 RGB 图像，连续 3 个 u8 代表一个像素（\([R_0, G_0, B_0, R_1, G_1, B_1...]\)）； 而对于带 Alpha 透明度通道的 RGBA 图像（例如本例中的 PNG），连续 4 个 u8 代表一个像素：\([R, G, B, A]\)。

15.3 引入极速轻量的现代 C 语言库：libspng

正如我们在 Section 15.2.2 中所讨论的，本项目使用的示例图像是一个采用 RGBA 颜色模型的 PNG 文件。 PNG 文件不是裸数据，它内部经过了复杂的 Deflate 压缩与滤波。 要解压和编码 PNG，老牌官方库 libpng 代码繁重且 API 晦涩； 因此，在这个项目中我会使用一个更现代的替代方案，即 libspng 库3。我选择这个 C 库，是因为它比 libpng 简单得多，而且各项操作的性能都很好。

本地编译本项目前，请确保系统中已经安装了 libspng 开发包（可参考官方构建指南4）。

15.4 第一阶段：读取并解码 PNG 像素

由于 libspng 是一个 C 语言库，其文件与 I/O 操作主要基于 C 语言的 FILE 指针。因此，这里我们使用 C 标准库 stdio.h 中的 fopen() 函数来打开 PNG 文件，而不是使用我们在 Chapter 13 中介绍的 Zig 原生 openFile() 方法。利用 @cImport，我们直接引入 stdio.h 和 spng.h：

const c = @cImport({
    @cDefine("_NO_CRT_STDIO_INLINE", "1");
    @cInclude("stdio.h");
    @cInclude("spng.h");
});

const path = "pedro_pascal.png";
const file_descriptor = c.fopen(path, "rb");
if (file_descriptor == null) {
    @panic("Could not open file!");
}
const ctx = c.spng_ctx_new(0) orelse unreachable;
_ = c.spng_set_png_file(
    ctx, @ptrCast(file_descriptor)
);

别忘了用完关闭文件句柄：

if (c.fclose(file_descriptor) != 0) {
    return error.CouldNotCloseFileDescriptor;
}

15.4.1 1. 读取 PNG 头信息（IHDR）

现在，上下文对象 ctx 已经知道我们的 PNG 文件 pedro_pascal.png，因为它可以访问这个文件的文件描述符对象。我们要做的第一件事是读取 PNG 文件的”图像头部分”。这一部分包含关于 PNG 文件的一些基本信息，比如图像像素数据的位深、文件所用的颜色模型、图像的尺寸（以像素数表示的高度和宽度）等。

为了方便，我会把这个”读取图像头”的操作封装成一个名为 get_image_header() 的小函数。这个函数只需调用 spng_get_ihdr() 函数即可。libspng 中的这个函数负责读取图像头数据，并把它存入一个名为 spng_ihdr 的 C 结构体。因此，spng_ihdr 类型的对象是一个包含 PNG 文件图像头部分数据的 C 结构体。

由于这个 Zig 函数接收一个 C 对象（libspng 的上下文对象）作为输入，我按照 Section 14.5 中讨论的建议，把函数参数 ctx 标注为”指向上下文对象的指针”（*c.spng_ctx）。

fn get_image_header(ctx: *c.spng_ctx) !c.spng_ihdr {
    var image_header: c.spng_ihdr = undefined;
    if (c.spng_get_ihdr(ctx, &image_header) != 0) {
        return error.CouldNotGetImageHeader;
    }
    return image_header;
}

var image_header = try get_image_header(ctx);

还要注意，在这个函数中，我检查了 spng_get_ihdr() 函数调用是否返回了一个非零的整数值。libspng 库中的大多数函数都返回一个状态码作为结果，状态码”零”表示”成功”。所以任何非零的状态码都表示在运行 spng_get_ihdr() 时发生了错误。这就是为什么当函数返回的状态码不为零时，我会从函数中返回一个错误值。

15.4.2 2. 为像素数据分配空间

在从 PNG 文件中读取像素数据之前，我们需要分配足够的空间来存放这些数据。但为了分配这样的空间，首先需要知道要分配多少空间。计算这个空间的大小显然需要用到图像的尺寸，但还有其他因素也会影响这个数字，比如图像所用的颜色模型、位深等。

总之，这一切都意味着计算所需空间的大小并不是一件简单的事。这就是为什么 libspng 库提供了一个名为 spng_decoded_image_size() 的工具函数来替我们计算这个大小。同样，我会把围绕这个 C 函数的逻辑封装成一个名为 calc_output_size() 的小 Zig 函数。可以看到，这个函数返回一个整数值，表示需要分配的空间大小。

fn calc_output_size(ctx: *c.spng_ctx) !u64 {
    var output_size: u64 = 0;
    const status = c.spng_decoded_image_size(
        ctx, c.SPNG_FMT_RGBA8, &output_size
    );
    if (status != 0) {
        return error.CouldNotCalcOutputSize;
    }
    return output_size;
}

你可能会问自己，SPNG_FMT_RGBA8 这个值是什么意思。这个值实际上是 C 头文件 spng.h 中定义的一个枚举值，这个枚举用于标识一种”PNG 格式”。更确切地说，它标识的是使用 RGBA 颜色模型、位深为 8 位的 PNG 文件。所以，把这个枚举值作为输入传给 spng_decoded_image_size() 函数，就是在告诉这个函数，按照遵循”RGBA 颜色模型、8 位位深”格式的 PNG 文件来计算解码后像素数据的大小。

有了这个函数，我们就可以配合分配器对象，分配一个足够大的字节（u8 值）数组来存放图像解码后的像素数据。注意，我用 @memset() 把整个数组初始化为零。

const output_size = try calc_output_size(ctx);
var buffer = try allocator.alloc(u8, output_size);
@memset(buffer[0..], 0);

15.4.3 3. 解码图像数据

现在我们有了存放图像解码后像素数据所需的空间，可以开始用 C 函数 spng_decode_image() 真正地解码并从图像中提取像素数据了。

下面的 Zig 函数 read_data_to_buffer() 概括了读取解码后像素数据并把它存入输入缓冲区所需的步骤。注意，这个函数封装了围绕 spng_decode_image() 函数的逻辑。此外，我们再次使用 SPNG_FMT_RGBA8 枚举值，告诉相应的函数，正在解码的 PNG 图像使用 RGBA 颜色模型和 8 位位深。

fn read_data_to_buffer(ctx: *c.spng_ctx, buffer: []u8) !void {
    const status = c.spng_decode_image(
        ctx,
        buffer.ptr,
        buffer.len,
        c.SPNG_FMT_RGBA8,
        0
    );

    if (status != 0) {
        return error.CouldNotDecodeImage;
    }
}

有了这个函数，就可以把它应用到上下文对象，以及上一节为存放图像解码后像素数据而分配的缓冲区对象上：

try read_data_to_buffer(ctx, buffer[0..]);

15.4.4 查看像素数据

现在像素数据已经存放在我们的”缓冲区对象”中，可以快速看一下这些字节。在下面的例子中，我们查看解码后像素数据的前 12 个字节。

如果仔细看这些值，你可能会注意到，序列中每隔 4 个字节就有一个 255。碰巧的是，这正是 u8 值所能表示的最大整数值。所以，如果把 0 到 255 这个 u8 值所能表示的整数范围看作一个从 0% 到 100% 的刻度，这些 255 值在这个刻度上实际上就是 100%。

回顾 Section 15.2.2，我在那一节中说过，我们的 PNG 文件 pedro_pascal.png 使用 RGBA 颜色模型，它会给图像中的每个像素添加一个 alpha（即透明度）字节。因此，图像中的每个像素由 4 个字节表示。由于这里查看的是图像的前 12 个字节，这意味着我们看到的是图像中前 \(12 / 4 = 3\) 个像素的数据。

所以，从这前 12 个字节（即这 3 个像素）每隔 4 个字节出现一个 255 的情况来看，可以说图像中的每个像素的 alpha（即透明度）很可能都被设为 100%。这不一定成立，但是可能性最大的情况。另外，如果看一下图像本身（回顾 Figure 15.1），可以看到整幅图像的透明度没有变化，这也支持了这一推测。

try stdout.print("{any}\n", .{buffer[0..12]});
try stdout.flush();
{
    200, 194, 216, 255, 203, 197,
    219, 255, 206, 200, 223, 255
}

从上面的结果可以看到，这幅图像的第一个像素的红色为 200、绿色为 194、蓝色为 216。我怎么知道颜色在序列中出现的顺序？如果你还没猜到，答案就在缩写 RGB 中：先是红色（RED），然后是绿色（GREEN），最后是蓝色（BLUE）。如果按照 0% 到 100%（0 到 255）的刻度换算这些整数值，就得到 78% 的红色、76% 的绿色和 85% 的蓝色。

15.5 第二阶段：施加经典人眼灰度滤镜算法

现在我们有了图像中每个像素的数据，可以专注于对这些像素应用图像滤镜了。请记住，我们的目标是对图像应用灰度滤镜。灰度滤镜是把彩色图像转换为灰度图像的滤镜。

把彩色图像转换为灰度图像有多种不同的公式和策略，但这些策略通常都涉及对每个像素的颜色做一些数学运算。在这个项目中，我们将使用最通用的公式，如下所示。在这个公式中，\(r\) 表示像素的红色，\(g\) 表示绿色，\(b\) 表示蓝色，\(p'\) 表示像素的线性亮度。

\[ p' = (0.2126 \times r) + (0.7152 \times g) + (0.0722 \times b) \tag{15.1}\]

Equation 15.1 是计算像素线性亮度的公式。值得注意的是，这个公式只适用于像素使用 sRGB 色彩空间的图像，sRGB 是网络上的标准色彩空间，所以理想情况下，网络上的所有图像都应该使用这个色彩空间。幸运的是，我们这里的情况正是如此：pedro_pascal.png 这幅图像使用的就是 sRGB 色彩空间，因此我们可以使用 Equation 15.1。你可以在维基百科的灰度（grayscale）词条中进一步了解这个公式 (Wikipedia 2024)。

下面的 apply_image_filter() 函数概括了将 Equation 15.1 应用到图像像素上所需的步骤。我们只需把这个函数应用到包含像素数据的缓冲区对象上，这个缓冲区对象中存储的像素数据就会变成图像的灰度版本。

fn apply_image_filter(buffer: []u8) !void {
    const len = buffer.len;
    const red_factor: f16 = 0.2126;
    const green_factor: f16 = 0.7152;
    const blue_factor: f16 = 0.0722;
    var index: u64 = 0;
    while (index < len) : (index += 4) {
        const rf: f16 = @floatFromInt(buffer[index]);
        const gf: f16 = @floatFromInt(buffer[index + 1]);
        const bf: f16 = @floatFromInt(buffer[index + 2]);
        const y_linear: f16 = (
            (rf * red_factor) + (gf * green_factor)
            + (bf * blue_factor)
        );
        buffer[index] = @intFromFloat(y_linear);
        buffer[index + 1] = @intFromFloat(y_linear);
        buffer[index + 2] = @intFromFloat(y_linear);
    }
}

try apply_image_filter(buffer[0..]);

15.6 第三阶段：将处理后的图片重新打包写盘

将处理好的内存缓冲区重新编码成合规的 PNG 文件：

fn save_png(image_header: *c.spng_ihdr, buffer: []u8) !void {
    const path = "pedro_pascal_filter.png";
    const file_descriptor = c.fopen(path.ptr, "wb");
    if (file_descriptor == null) {
        return error.CouldNotOpenFile;
    }
    const ctx = (
        c.spng_ctx_new(c.SPNG_CTX_ENCODER)
        orelse unreachable
    );
    defer c.spng_ctx_free(ctx);
    _ = c.spng_set_png_file(ctx, @ptrCast(file_descriptor));
    _ = c.spng_set_ihdr(ctx, image_header);

    const encode_status = c.spng_encode_image(
        ctx,
        buffer.ptr,
        buffer.len,
        c.SPNG_FMT_PNG,
        c.SPNG_ENCODE_FINALIZE
    );
    if (encode_status != 0) {
        return error.CouldNotEncodeImage;
    }
    if (c.fclose(file_descriptor) != 0) {
        return error.CouldNotCloseFileDescriptor;
    }
}

try save_png(&image_header, buffer[0..]);

15.7 编写 build.zig 构建链接脚本

最后，运用我们在 Chapter 9 中学到的 Zig 构建系统知识，编写 build.zig 将代码与 C 标准库、libspng 以及数学库链接起来：

const std = @import("std");
pub fn build(b: *std.Build) void {
    const exe = b.addExecutable(.{
        .name = "image_filter",
        .root_module = b.createModule(.{
            .root_source_file = b.path("src/image_filter.zig"),
            .target = b.graph.host,
            .link_libc = true
        })
    });
    // 链接系统安装的 libspng 和数学库
    exe.root_module.linkSystemLibrary("spng", .{});
    exe.root_module.linkSystemLibrary("m", .{});
    b.installArtifact(exe);
}

在终端执行如下命令即可完成项目构建：

zig build

运行编译出的可执行程序后，当前工作目录下就会生成处理完毕的黑白灰度图像（如 Figure 15.2 所示）。
