8  单元测试（Unit Tests）

在本章中，我们将深入探讨 Zig 中的单元测试（Unit Tests）工作流，以及如何使用 zig 编译器的 test 命令运行测试。

8.1 认识原生 test 代码块

在 Zig 中，单元测试编写在 test 声明块（或简称 test 代码块）内部。每个 test 块都以关键字 test 开头，后面可以可选地跟一个字符串字面量作为标签，用来标识该测试块所测试的具体功能。

在下面的示例中，我们测试两个对象（a 和 b）之和是否等于 4。Zig 标准库提供的 expect() 函数接收一个布尔逻辑表达式作为输入：如果表达式求值为 true，测试通过；如果为 false，测试失败。你可以在 test 块中编写任意合法的 Zig 代码来初始化测试环境或待测对象：

const std = @import("std");
const expect = std.testing.expect;
test "testing simple sum" {
    const a: u8 = 2;
    const b: u8 = 2;
    try expect((a + b) == 4);
}
1/1 t.test.testing simple sum... OK
All 1 tests passed.

在同一个 .zig 源码文件里，你可以一口气写任意多个 test 块。 而且最棒的是：test 块可以直接与业务代码混写在同一个文件里！ 当你执行我们在 Section 1.2.5 中介绍过的 build、build-exe、build-obj 或 build-lib 命令构建常规目标时，zig 编译器会自动忽略这些 test 块（默认仅检查语法，只有当你明确要求运行测试时才会编译并执行它们）。

如果你翻阅 Zig 标准库的源码1（例如 array_list 模块2），就会看到官方代码普遍将 test 块与被测功能的源码写在同一个文件中。

当然，每位开发者的工程偏好不同。如果你更习惯将单元测试与业务源码分开存放，也可以在项目中单独创建一个 tests 目录，专门编写只包含单元测试的 Zig 模块（就像在 Python 项目中使用 pytest 一样）。

8.2 怎样运行单元测试

既然日常编译会忽略 test 块，那怎么跑测试呢？ 直接使用编译器的 zig test 子命令即可：

zig test simple_sum.zig

终端会飞速扫过该文件中的每一个 test 块并输出测试通过状态：

1/1 simple_sum.test.testing simple sum... OK
All 1 tests passed.

8.3 核心利器：自动检测内存泄漏（Testing Allocator）

Zig 的一大优势在于提供了强大的工具来帮助程序员避免并主动检测内存泄漏（Memory Leak）和双重释放（Double Free）等内存问题。除了 defer 关键字外，Zig 标准库还专门提供了一个能自动检测内存问题的特殊分配器对象：std.testing.allocator。

正如我们在 Section 3.1.5 中所述，在堆上分配内存需要借助分配器对象，且由哪个分配器申请的内存就必须由同一个分配器释放。因此，如果你希望测试函数内部的内存分配逻辑是否安全，只需在单元测试中将 std.testing.allocator 作为参数传给待测函数即可。

看下面这个存在明显内存泄漏的示例：函数分配了内存却在返回前未将其释放。当我们在 test 块中传入 std.testing.allocator 执行该函数时，测试分配器捕获到了内存泄漏，并打印出 "memory leaked" 错误信息以及泄漏点的精确调用栈轨迹（Stack Trace）：

const std = @import("std");
const Allocator = std.mem.Allocator;
fn some_memory_leak(allocator: Allocator) !void {
    const buffer = try allocator.alloc(u32, 10);
    _ = buffer;
    // 故意不释放内存直接 return 退出！
}

test "memory leak" {
    const allocator = std.testing.allocator;
    try some_memory_leak(allocator);
}

跑 zig test 时，测试立刻爆红，精准指认罪魁祸首：

Test [1/1] leak_memory.test.memory leak...
    [gpa] (err): memory address 0x7c1fddf39000 leaked:
./ZigExamples/debugging/leak_memory.zig:4:39: 0x10395f2
    const buffer = try allocator.alloc(u32, 10);
                                      ^
./ZigExamples/debugging/leak_memory.zig:12:25: 0x10398ea
    try some_memory_leak(allocator);

... more stack trace

8.4 测试预期错误（Testing errors）

另一类常见的单元测试是验证函数在特定条件下是否会返回预期的错误。在 C++ 中，你通常会使用 Catch2 测试框架3中的 REQUIRE_THROWS() 或 CHECK_THROWS()；在 Python 项目中，通常会使用 pytest 的 raises() 函数4；而在 Rust 中则会配合使用 assert_eq!() 与 Err()。

在 Zig 中，我们使用 std.testing 模块下的 expectError() 函数：第一个参数传入预期返回的错误值（如 error.OutOfMemory），第二个参数传入预期会失败的函数调用表达式。

在下面的代码示例中，alloc_error() 函数试图为 ibuffer 分配 100 字节的内存，但在 test 块中我们传入的 FixedBufferAllocator() 底层缓冲区只有 10 字节空间，因此调用 alloc_error() 会触发 OutOfMemory 错误：

const std = @import("std");
const Allocator = std.mem.Allocator;
const expectError = std.testing.expectError;
fn alloc_error(allocator: Allocator) !void {
    var ibuffer = try allocator.alloc(u8, 100);
    defer allocator.free(ibuffer);
    ibuffer[0] = 2;
}

test "testing error" {
    var buffer: [10]u8 = undefined;
    var fba = std.heap.FixedBufferAllocator.init(&buffer);
    const allocator = fba.allocator();
    try expectError(error.OutOfMemory, alloc_error(allocator));
}
1/1 t.test.testing error... OK
All 1 tests passed.

如果 alloc_error() 返回了其他类型的错误或者没有报错，expectError() 就会判定该单元测试失败。

8.5 测试相等性（Testing simple equalities）

在 Zig 中，除了使用 expect() 配合 == 运算符测试相等性外，std.testing 还提供了几个非常实用的相等断言辅助函数：expectEqual()、expectEqualSlices() 和 expectEqualStrings()。

  • expectEqual()：接收两个对象作为输入（第一个参数为期望值，第二个参数为实际结果），测试两个对象存储的值是否相等。在下例中，由于 v1 和 v2 的值不同，测试失败并打印出期望值与实际值的差异：
const std = @import("std");
test "values are equal?" {
    const v1 = 15;
    const v2 = 18;
    try std.testing.expectEqual(v1, v2);
}
1/1 ve.test.values are equal?...
    expected 15, found 18
    FAIL (TestExpectedEqual)
ve.zig:5:5: test.values are equal? (test)
    try std.testing.expectEqual(v1, v2);
    ^
0 passed; 0 skipped; 1 failed.
  • expectEqualSlices()：expectEqual() 不能直接用于比较数组；若要测试两个数组或切片是否相等，应使用 expectEqualSlices()。它接收三个参数：第一个参数是数组元素的数据类型，第二和第三个参数是要比较的两个数组/切片对象：
const std = @import("std");
test "arrays are equal?" {
    const array1 = [3]u32{1, 2, 3};
    const array2 = [3]u32{1, 2, 3};
    try std.testing.expectEqualSlices(
        u32, &array1, &array2
    );
}
1/1 t.test.arrays are equal?... OK
All 1 tests passed.

（译注：在 Zig 0.17.1 中，expectEqual() 其实可以比较两个数组，它会逐个比较元素。但如果传入的是切片，它只比较两个切片的指针和长度，不比较内容。所以要比较切片的内容，还是应该用 expectEqualSlices()。）

  • expectEqualStrings()：专门用于测试两个字符串对象是否相等。如果发现两段字符串存在差异，它会报错并直观地打印出两者的首个差异位置：
const std = @import("std");
test "strings are equal?" {
    const str1 = "hello, world!";
    const str2 = "Hello, world!";
    try std.testing.expectEqualStrings(
        str1, str2
    );
}
1/1 t.test.strings are equal?...
====== expected this output: =========
hello, world!␃
======== instead found this: =========
Hello, world!␃
======================================
First difference occurs on line 1:
expected:
hello, world!
^ ('\x68')
found:
Hello, world!
^ ('\x48')
