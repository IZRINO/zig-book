10  错误处理与联合体

这一章我想讲讲 Zig 里怎样做错误处理。前面我们已经简单学过 Zig 里处理错误的一种办法，就是 Section 1.2.3 里介绍的 try 关键字。但其他办法我们还没学，比如 catch 关键字。这一章我也想讲讲 Zig 里怎样创建联合体类型。

10.1 进一步认识 Zig 里的错误

在讲错误处理怎么做之前，我们得先多了解一点：在 Zig 里，错误到底是什么。错误其实是一个值 (Zig Software Foundation 2024a)。换句话说，你的 Zig 程序里发生错误，意味着代码库的某处正在生成一个错误值。错误值和你在 Zig 代码里创建的任何整数值是类似的。你可以把一个错误值作为输入传给函数，也可以把它转换（或者说强制转换）成另一种错误值。

这和 C++、Python 里的异常有一些相似之处。因为在 C++ 和 Python 里，try 块里发生异常时，你可以用 catch 块（C++）或 except 块（Python）捕获 try 块里产生的异常，并把它作为输入传给函数。

不过，Zig 里的错误值和异常的待遇很不一样。首先，你不能在 Zig 代码里忽略错误值。意思是，如果源代码的某处出现了一个错误值，这个错误值必须以某种方式被显式处理。这也意味着，你不能像对待普通值和对象那样，把错误值赋给下划线来丢掉它。

下面的源代码就是一个例子。这里我们试图打开一个在我电脑上不存在的文件，结果 openFile() 函数返回了一个显而易见的错误值 FileNotFound。可因为我把这个函数的结果赋给了下划线，我最终是在试图丢掉一个错误值。

zig 编译器发现了这个错误，并给出一条编译错误，告诉我正在试图丢掉一个错误值。它还加了一条 note，建议用 try、catch 或 if 语句来显式处理这个错误值。这条 note 强调的是：在 Zig 里，每一个可能的错误值都必须被显式处理。

const cwd = std.Io.Dir.cwd();
_ = cwd.openFile(
    init.io, "doesnt_exist.txt", .{ .mode = .write_only }
);
t.zig:8:17: error: error set is discarded
t.zig:8:17: note: consider using 'try', 'catch', or 'if'

10.1.1 从函数返回错误

正如我们在 Section 1.2.3 里说过的，一个函数如果可能返回错误值，它的返回类型标注里通常会有一个感叹号（!）。这个感叹号表示这个函数的结果可能是一个错误值，而 zig 编译器会强迫你始终显式处理「这个函数返回了错误值」的情况。

看看下面的 print_name() 函数。这个函数可能在调用 stdout.print() 时返回错误，因此它的返回类型（!void）里带了一个感叹号。

fn print_name(stdout: *std.Io.Writer) !void {
    try stdout.print("My name is Pedro!", .{});
    try stdout.flush();
}

在上面的例子里，我们用感叹号告诉 zig 编译器，这个函数可能返回某个错误。可究竟返回的是哪个错误？眼下我们没有指定一个具体的错误值。眼下我们只知道，可能会返回某个错误值（不管它是什么）。

但事实上，如果你愿意，可以清清楚楚地指定这个函数可能返回哪些错误值。Zig 标准库里这样的例子很多。拿 http.Client 模块里的这个 fill() 函数为例。这个函数返回的要么是 ReadError 类型的错误值，要么是 void。

pub fn fill(conn: *Connection) ReadError!void {
    // The body of this function ...
}

把你预期会返回的错误值具体标出来，这个想法很有意思。因为它们会自动变成函数的某种文档，而且这还让 zig 编译器能对你的代码再做一些检查。编译器可以检查：函数内部是不是还生成了别的类型的错误值，而这些错误值并没有算进这个返回类型标注里。

总之，你可以把可能从函数返回的错误类型列在感叹号的左边。合法的值则留在感叹号的右边。所以语法格式变成：

<error-value>!<valid-value>

10.1.2 错误集

可如果一个函数可能返回不同类型的错误呢？有这样的函数时，你可以把这个函数可能返回的所有这些不同类型的错误列出来，用的是 Zig 里我们称为错误集（error set）的一种结构。

错误集是联合体类型的一种特殊情况。它是一个里面装着错误值的联合体。不是所有编程语言都有「联合体对象」这个概念。但简单说，联合体就是一组数据类型。联合体用来允许一个对象具有多种数据类型。例如，x、y 和 z 的一个联合体，意味着一个对象可以是 x 类型，或 y 类型，或 z 类型。

联合体我们会在 Section 10.3 里讲得更深。不过你可以这样写一个错误集：在一对花括号前面写上关键字 error，然后在这对花括号里列出可以从函数返回的错误值。

下面的 resolvePath() 函数就是一个例子，它来自 Zig 标准库的 introspect.zig 模块。从它的返回类型标注可以看出，这个函数返回的要么是：1）一个合法的 u8 值切片（[]u8）；要么是 2）错误集里列出的三种不同类型的错误值之一（OutOfMemory、Unexpected 等）。这是错误集的一个用法示例。

（译注：在 Zig 0.17.1 里，这个函数在 lib/std/zig.zig，不在 introspect.zig。签名是 resolvePath(gpa, cwd_resolved, paths) Allocator.Error![]u8，和这里展示的参数、错误集都不一样。）

pub fn resolvePath(
    ally: mem.Allocator,
    p: []const u8,
) error{
    OutOfMemory,
    CurrentWorkingDirectoryUnlinked,
    Unexpected,
}![]u8 {
    // The body of the function ...
}

这是标注 Zig 函数返回值的一种合法方式。不过，如果你去翻构成 Zig 标准库的那些模块，会注意到在大多数情况下，程序员更愿意给这个错误集起一个有描述性的名字，然后在返回类型标注里使用错误集的这个名字（或者说这个「标签」），而不是直接把错误集写在那里。

前面 fill() 函数里的那个 ReadError 错误集就是这样，它定义在 http.Client 模块里。所以是的，我前面把 ReadError 讲得好像它只是一个普通的、单个的错误值，可事实上，它是 http.Client 模块里定义的一个错误集，因此它实际代表的是 fill() 函数内部可能发生的一组不同的错误值。

看看下面复述的 ReadError 定义。注意，我们把这些不同的错误值归到一个对象里，然后把这个对象用在函数的返回类型标注中。像前面展示的 fill() 函数，或者同一个模块里的 readvDirect() 函数，下面也复述了它。

pub const ReadError = error{
    TlsFailure,
    TlsAlert,
    ConnectionTimedOut,
    ConnectionResetByPeer,
    UnexpectedReadFailure,
    EndOfStream,
};
// Some lines of code
pub fn readvDirect(
        conn: *Connection,
        buffers: []std.posix.iovec
    ) ReadError!usize {
    // The body of the function ...
}

所以，错误集只是一种方便的办法，把一组可能的错误值归到一个对象里，或者说归成一种错误值类型。

（译注：Zig 0.17.1 的 std.http.Client 里仍然有 ReadError，但它是 std.crypto.tls.Client.ReadError || Io.net.Stream.Reader.Error，不是上面那个手写的错误集。这一版的 Client 里也没有 fill() 和 readvDirect()。）

10.1.3 转换错误值

假设你有两个不同的错误集，名叫 A 和 B。如果错误集 A 是错误集 B 的超集，那你就可以把 B 的错误值转换（或者说强制转换）成 A 的错误值。

错误集只是一组错误值。所以，如果错误集 A 包含错误集 B 的全部错误值，那么 A 就是 B 的超集。你也可以说，错误集 B 是错误集 A 的子集。

下面的例子演示的就是这个想法。因为 A 包含 B 的全部值，所以 A 是 B 的超集。用数学记号，我们会说 \(A \supset B\)。因此，我们可以把一个来自 B 的错误值作为输入传给 cast() 函数，并把这个输入隐式转换成同一个错误值，只不过属于 A 这个集合。

const std = @import("std");
const A = error{
    ConnectionTimeoutError,
    DatabaseNotFound,
    OutOfMemory,
    InvalidToken,
};
const B = error {
    OutOfMemory,
};

fn cast(err: B) A {
    return err;
}

test "coerce error value" {
    const error_value = cast(B.OutOfMemory);
    try std.testing.expect(
        error_value == A.OutOfMemory
    );
}

  ll 1 tests passed.

10.2 怎样处理错误

现在我们多了解了一些 Zig 里的错误是什么，来讨论处理这些错误的现成办法。它们是：

  • try 关键字；
  • catch 关键字；
  • if 语句；
  • errdefer 关键字。

10.2.1 try 是什么意思？

正如我在前面几节说过的，当我们说一个表达式可能返回错误时，我们基本上指的是一个返回类型格式为 !T 的表达式。! 表示这个表达式返回的要么是一个错误值，要么是一个 T 类型的值。

在 Section 1.2.3 里，我介绍了 try 关键字以及在哪里用它。但我没有讲这个关键字究竟对你的代码做了什么，换句话说，我还没有解释 try 在你的代码里是什么意思。

本质上，当你在一个表达式上使用 try 关键字时，你是在告诉 zig 编译器下面这些话：「嘿！帮我执行这个表达式。如果这个表达式返回错误，请把这个错误返回给我，并停住我的程序的执行。如果这个表达式返回的是合法值，那就返回这个值，然后继续。」

换句话说，try 关键字本质上是一种进入 panic 模式的策略：一旦发生错误，就停住程序的执行。用 try 关键字，你是在告诉 zig 编译器，如果那个特定的表达式发生了错误，停住程序的执行是最合理的策略。

（译注：这里把 try 说成会让程序进入 panic、停住整个程序，说得过了。try 的实际效果是：表达式返回错误时，把这个错误从当前函数返回给调用者。只有这个错误一直没有被处理、最终从没有人接住的地方冒出去，程序才会因为未处理的错误而终止。）

10.2.2 catch 关键字

好，现在我们搞清楚了 try 是什么意思，来讲 catch。这里有一个重要的细节：你可以用 try 或 catch 来处理错误，但你不能把 try 和 catch 一起用。换句话说，在 Zig 语言里，try 和 catch 是不同的、完全分开的两种策略。

这不太常见，也和其他语言不一样。大多数采用 try catch 模式的编程语言（比如 C++、R、Python、JavaScript 等），通常把这两个关键字一起用，凑成正确处理错误的完整逻辑。总之，Zig 在 try catch 模式上试的是另一种做法。

所以，我们已经知道 try 是什么意思，也知道 try 和 catch 都应该单独使用、彼此分开。可 catch 在 Zig 里究竟做什么？用 catch，我们可以构造一块逻辑，在当前表达式发生错误值时去处理它。

看看下面的代码示例。我们再次回到前面那个例子：试图打开一个在我电脑上不存在的文件。但这一次，我用 catch 真正实现一段处理错误的逻辑，而不是立刻停住执行。

更具体地说，在这个例子里，我在返回错误、停住程序执行之前，用一个 logger 对象往系统里记一些日志。例如，这可能是一个我并不能完全掌控的复杂系统的某部分代码，我想在程序崩溃之前把这些日志记下来，以便以后调试（比如，也许我没法编译整个程序，也没法用调试器好好调试它。于是这些日志可能是绕过这道障碍的一种可行办法）。

pub fn main(init: std.process.Init) !void {
    const cwd = std.Io.Dir.cwd();
    const file = cwd.openFile(
        init.io, "doesnt_exist.txt", .{}
    ) catch |err| {
        logger.record_context();
        logger.log_error(err);
        return err;
    };
}

因此，我们用 catch 来创建一块用来处理错误的表达式。我可以像上面的例子那样，从这块表达式里返回错误值，这会让程序进入 panic 模式，并停住执行。但我也可以从这块代码里返回一个合法值，这个值会被存进 file 对象。

注意，和 try 不同，我们不是把关键字写在可能返回错误的表达式前面，而是把 catch 写在表达式后面。我们可以打开一对竖线（|），它捕获表达式返回的错误值，并让这个错误值在 catch 块的作用域里以名为 err 的对象可用。换句话说，因为我在代码里写了 |err|，我就可以通过 err 这个对象访问表达式返回的错误值。

虽然这是 catch 最常见的用法，你也可以用这个关键字以「默认值」的风格来处理错误。也就是说，如果表达式返回错误，我们就改用默认值。否则，我们就用表达式返回的合法值。

Zig 的官方语言参考给这种「默认值」策略提供了一个很好的例子，用的就是 catch。这个例子复述如下。注意，我们试图从一个名为 str 的字符串对象解析某个无符号整数。换句话说，这个函数试图把一个 []const u8 类型的对象（也就是一个字符数组、一个字符串，等等）变成一个 u64 类型的对象。

但 parseU64() 函数做的这个解析过程可能失败，导致一个运行时错误。这个例子里的 catch 关键字提供了一个备用值（13），在 parseU64() 函数引发错误时使用。所以，下面这个表达式本质上的意思是：「嘿！请帮我把这个字符串解析成 u64，并把结果存进对象 number。不过，如果发生错误，那就改用值 13。」

const number = parseU64(str, 10) catch 13;

所以，这个过程结束时，对象 number 里装的要么是从输入字符串 str 成功解析出来的一个 u64 整数，要么，如果解析过程中发生了错误，装的就是 catch 关键字作为「默认」或者说「备用」值提供的那个 u64 值 13。

10.2.3 使用 if 语句

现在，你也可以用 if 语句来处理 Zig 代码里的错误。在下面的例子里，我复述前一个例子：用一个名为 parseU64() 的函数，试图从输入字符串解析出一个整数值。

我们在「if」里面执行这个表达式。如果这个表达式返回的是错误值，if 语句的「if 分支」（或者说「真分支」）不会执行。如果这个表达式返回的是合法值，这个值就会被解包到 number 对象里。

这意味着，如果 parseU64() 表达式返回了一个合法值，这个值就可以在这个「if 分支」（也就是「真分支」）的作用域里使用，用的是我们列在一对竖线字符（|）里的那个对象，也就是对象 number。

如果发生了错误，我们可以用 if 语句的「else 分支」（或者说「假分支」）来处理错误。在下面的例子里，我们用 if 语句里的 else 把错误值（由 parseU64() 返回的那个）解包到 err 对象里，并处理这个错误。

if (parseU64(str, 10)) |number| {
    // do something with `number` here
} else |err| {
    // handle the error value.
}

现在，如果你正在执行的表达式会返回不同类型的错误值，而你想对每一种错误值采取不同的动作，那么 try 和 catch 关键字，以及 if 语句这套办法，就变得有限了。

对这种情况，语言的官方文档建议把 switch 语句和 if 语句一起用 (Zig Software Foundation 2024b)。基本想法是：用 if 语句执行表达式，用「else 分支」把错误值传给一个 switch 语句，你在那里为表达式可能返回的每一种错误值定义一个不同的动作。

下面的例子演示的就是这个想法。我们先试图把一组任务加进（或者说登记进）一个队列。如果这个「登记过程」顺利，我们就接着试图把这些任务分发给系统里的 worker。如果这个「登记过程」返回了一个错误值，我们就在「else 分支」里用 switch 语句处理每一种可能的错误值。

if (add_tasks_to_queue(&queue, tasks)) |_| {
    distribute_tasks(&queue);
} else |err| switch (err) {
    error.InvalidTaskName => {
        // do something
    },
    error.TimeoutTooBig => {
        // do something
    },
    error.QueueNotFound => {
        // do something
    },
    // and all the other error options ...
}

10.2.4 errdefer 关键字

C 程序里一个常见的模式，是在程序执行期间发生错误时清理资源。换句话说，处理错误的一种常见方式，是在退出程序之前做「清理动作」。这保证运行时错误不会让程序泄漏系统的资源。

errdefer 关键字就是在这种不利局面下做这类「清理动作」的工具。这个关键字常用来在程序的执行因为生成了一个错误值而停住之前，清理（或者说释放）已分配的资源。

基本想法是给 errdefer 关键字提供一个表达式。然后，当且仅当当前作用域的执行期间发生了错误，errdefer 才会执行这个表达式。在下面的例子里，我们用一个分配器对象（我们在 Section 3.3 里介绍过）来创建一个新的 User 对象。如果我们成功创建并登记了这个新用户，这个 create_user() 函数就会把这个新的 User 对象作为返回值返回。

可如果出于某种原因，errdefer 那一行之后的某个表达式生成了错误值，例如在 db.add(user) 这个表达式里，那么在错误值从函数返回之前，在程序进入 panic 模式并停住当前执行之前，errdefer 登记的那个表达式会先执行。

（译注：正文写的是 db.add(user)，下面代码里调用的是 db.register_user(user)。）

fn create_user(db: Database, allocator: Allocator) !User {
    const user = try allocator.create(User);
    errdefer allocator.destroy(user);

    // Register new user in the Database.
    _ = try db.register_user(user);
    return user;
}

用 errdefer 销毁我们刚刚创建的 user 对象，我们就能保证：在程序的执行停住之前，为这个 user 对象分配的内存会被释放。因为如果表达式 try db.add(user) 返回了一个错误值，程序的执行就会停住，我们会失去对为 user 对象分配的那块内存的全部引用和控制。结果就是，如果在程序停住之前不释放与 user 对象关联的内存，我们就再也释放不了这块内存了。我们干脆失去了做正确事情的机会。这就是为什么在这种情况下 errdefer 是必不可少的。

为了把 defer 和 errdefer 的差别说清楚（我在 Section 2.1.3 和 Section 2.1.4 里描述过），也许值得再把这个题目往下谈一点。你脑子里可能还留着这个问题：「既然可以用 defer，为什么还要用 errdefer？」

虽然二者相似，errdefer 和 defer 关键字的关键差别在于，提供的那个表达式会在什么时候执行。defer 关键字总是在当前作用域结束时执行提供的表达式，不管你的代码是怎样退出这个作用域的。与此相对，errdefer 只在当前作用域发生错误时才执行提供的表达式。

如果当前作用域里分配的某项资源要到后面、在另一个作用域里才释放，这一点就变得重要了。create_user() 函数就是这样的例子。如果你仔细想这个函数，会注意到这个函数把 user 对象作为结果返回。

换句话说，如果 create_user() 函数成功返回，为 user 对象分配的内存并不会在这个函数内部被释放。所以，如果这个函数内部没有发生错误，user 对象会从函数返回，而跑在这个 create_user() 函数之后的代码，大概会负责释放 user 对象的内存。

可如果错误发生在 create_user() 函数内部呢？那又会怎样？这意味着你的代码会在这个 create_user() 函数里停住，因此跑在这个 create_user() 函数之后的代码根本不会跑，结果就是，在程序停住之前，user 对象的内存不会被释放。

这正是 errdefer 的理想场合。我们用这个关键字来保证：即使 create_user() 函数内部发生了错误，程序也会释放为 user 对象分配的内存。

如果你在同一个作用域里既分配又释放某个对象的内存，那就用 defer，然后就好了。也就是说，在这种情况下 errdefer 对你没有用。但如果你在作用域 A 里分配了一些内存，却要到以后、比如在作用域 B 里才释放这块内存，那么 errdefer 就变得有用了，可以在不稳妥的局面下避免内存泄漏。

10.3 Zig 里的联合体类型

联合体类型定义了一个对象可以是的一组类型。它像一份选项列表。每个选项都是对象可以呈现的一种类型。因此，Zig 里的联合体和 C 里的联合体意思相同，或者说角色相同。它们被用于同样的目的。你也可以说，Zig 里的联合体产生的效果，类似于在 Python 里使用 typing.Union 1。

例如，你可能在做一个 API，把数据送到托管在某套私有云基础设施上的数据湖。假设你在代码库里创建了不同的结构体，用来存放连接每种主流数据湖服务（Amazon S3、Azure Blob 等）所需要的信息。

现在，假设你还有一个名为 send_event() 的函数，它接收一个事件作为输入，以及一个目标数据湖，并把输入的事件送到目标数据湖参数所指定的那个数据湖。但这个目标数据湖可能是三种主流数据湖服务（Amazon S3、Azure Blob 等）中的任何一种。联合体可以在这里帮上忙。

下面定义的联合体 LakeTarget 允许 send_event() 的 lake_target 参数是 AzureBlob 类型的对象，或 AmazonS3 类型的对象，或 GoogleGCP 类型的对象。这个联合体允许 send_event() 函数在 lake_target 参数里接收这三种类型中任何一种的对象作为输入。

记住，这三种类型（AmazonS3、GoogleGCP 和 AzureBlob）各自是我们在源代码里定义的结构体。所以乍一看，它们在源代码里是分开的数据类型。但正是 union 关键字把它们统一成了一个名为 LakeTarget 的数据类型。

const LakeTarget = union {
    azure: AzureBlob,
    amazon: AmazonS3,
    google: GoogleGCP,
};

fn send_event(
    event: Event,
    lake_target: LakeTarget
) bool {
    // body of the function ...
}

一个联合体定义由一份数据成员列表组成。每个数据成员都是某种特定的数据类型。在上面的例子里，LakeTarget 联合体有三个数据成员（azure、amazon、google）。当你实例化一个使用联合体类型的对象时，这次实例化里你只能使用它的一个数据成员。

你也可以把这理解成：联合体类型的数据成员一次只能激活一个，其他数据成员保持未激活，并且不能访问。例如，如果你创建了一个使用 azure 数据成员的 LakeTarget 对象，你就不能再使用或访问数据成员 google 或 amazon。就好像这些其他数据成员在 LakeTarget 类型里根本不存在一样。

你可以在下面的例子里看到这个逻辑。注意，我们先用 azure 数据成员来实例化这个联合体对象。结果就是，这个 target 对象里面只包含 azure 数据成员。这个对象里只有这个数据成员是激活的。这就是为什么这个代码示例的最后一行是非法的。因为我们试图实例化数据成员 google，而它对这个 target 对象来说当前是未激活的，结果程序进入 panic 模式，用一条响亮的错误信息警告我们这个错误。

var target = LakeTarget {
    .azure = AzureBlob.init()
};
// Only the `azure` data member exist inside
// the `target` object, and, as a result, this
// line below is invalid:
target.google = GoogleGCP.init();
thread 2177312 panic: access of union field 'google' while
    field 'azure' is active:
    target.google = GoogleGCP.init();
          ^

所以，实例化一个联合体对象时，你必须选择联合体类型里列出的一种数据类型（或者说一个数据成员）。在上面的例子里，我选择使用 azure 数据成员，结果所有其他数据成员都被自动停用，实例化对象之后你就不能再使用它们了。

你可以通过把整个枚举对象完全重新定义一遍，来激活另一个数据成员。在下面的例子里，我一开始使用 azure 数据成员。然后，我重新定义 target 对象，让它使用一个新的 LakeTarget 对象，这个对象使用的是 google 数据成员。

（译注：这里原文写成「整个枚举对象」。重新赋值的是联合体对象，不是枚举。）

var target = LakeTarget {
    .azure = AzureBlob.init()
};
target = LakeTarget {
    .google = GoogleGCP.init()
};

关于联合体类型，有一个挺特别的事实：一开始，你不能在 switch 语句里使用它们（switch 语句在 Section 2.1.2 里介绍过）。换句话说，如果你有一个例如 LakeTarget 类型的对象，你不能把这个对象作为输入交给 switch 语句。

可如果你真的需要这样做呢？如果你实际上需要把一个「联合体对象」提供给 switch 语句呢？这个问题的答案依赖 Zig 里另一种特殊类型，也就是带标签联合体（tagged unions）。要创建带标签联合体，你要做的就是在联合体声明里加上一个枚举类型。

作为 Zig 里带标签联合体的例子，看看下面的 Registry 类型。这个类型来自 Zig 仓库里的 grammar.zig 模块 2。这个联合体类型列出了不同类型的 registry。但注意这一次，union 关键字后面用了 (enum)。正是这一点使这个联合体类型成为带标签联合体。因为是带标签联合体，Registry 类型的对象就可以作为输入用在 switch 语句里。你要做的就是这些。只要在 union 声明里加上 (enum)，就可以在 switch 语句里使用它。

pub const Registry = union(enum) {
    core: CoreRegistry,
    extension: ExtensionRegistry,
};
