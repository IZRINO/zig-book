6  指针与可选类型（Pointers and Optionals）

在紧接着的下一个实战项目中，咱们要手写一个属于自己的轻量 HTTP 服务器。 不过在动手造服务器之前，有一门系统底层开发的硬功夫必须拿下——指针（Pointers）与可选类型（Optionals）。 Zig 的指针和 C 的指针很像，但多了一些额外的好处。

说白了，指针就是一个存放内存地址的对象。这个地址就是某个值在内存中的存放位置。这个值可以是任何值，大多数时候来自代码里的另一个对象（或变量）。

看下面这个简单直观的例子：

const number: u8 = 5;
const pointer = &number;
_ = pointer;

在 Zig 里取对象地址用经典的取地址符 &。把 number 的地址取出来赋给 pointer，pointer 就成了一个指针。

拿到指针后，怎么顺藤摸瓜拿到（或者修改）它指向的真实数据呢？这个动作叫做解引用（Dereferencing）。 在 Zig 里，解引用的语法是在指针后面加 .*：

const number: u8 = 5;
const pointer = &number;
const doubled = 2 * pointer.*;
std.debug.print("{d}\n", .{doubled});
10

这套 .* 语法非常舒服，因为它能极其自然地和方法调用链连在一起。还记得在 Section 2.3 中写的 User 结构体和它的 print_name() 方法吗？ 拿到了指向某个用户的指针，直接 pointer.*.print_name() 即可流畅链式调用：

const u = User.init(1, "pedro", "email@gmail.com");
const pointer = &u;
try pointer.*.print_name();
pedro

如果底层对象是可变的，我们也可以通过指针原地更新它的值：

var number: u8 = 5;
const pointer = &number;
pointer.* = 6;
try stdout.print("{d}\n", .{number});
try stdout.flush();
6

我们在开发中之所以如此青睐指针，核心目的是避免昂贵的数据内存拷贝（Copy / Move）。 如果一个结构体体量很大，在函数调用或跨作用域传递时如果按值拷贝，CPU 得老老实实搬运大量字节；而如果传一个指针过去，只需要传递一个内存地址（在 64 位平台上是 8 字节），开销小得多。

6.1 常量对象 vs 变量对象下的指针规则

指针可以指向常量，也可以指向变量。 但请记住一条基本原则：指针必须始终尊重其所指向对象的可变性特征。因此，如果指针指向的是一个常量对象，你就不能通过该指针去修改它指向的值——正如我们在 Section 1.4 中所讨论的，常量对象的值是不可修改的。

例如，如果 number 是一个 const 常量对象，尝试通过 pointer 将其值修改为 6 会触发编译期错误：

const number = 5;
const pointer = &number;
pointer.* = 6;
p.zig:6:12: error: cannot assign to constant
    pointer.* = 6;

把 number 声明为 var 变量后，通过指针写值才能畅通无阻：

var number: u8 = 5;
const pointer = &number;
pointer.* = 6;
try stdout.print("{d}\n", .{number});
try stdout.flush();
6

在类型签名上区分得一清二楚： - 指向常量的指针，类型是 *const T（只读，无法通过它修改数据）； - 指向变量的指针，类型是 *T（可读可写）。

上面讨论的是“被指针指向的值”是否为常量；那么指针对象自身呢？如果把指针对象本身声明为 const（如前面的例子），我们就不能修改指针对象内部存储的内存地址；而如果将 pointer 声明为 var 变量对象，我们就可以随时改变它所指向的目标地址（例如从指向 c1 改为指向 c2）：

const c1: u8 = 5;
const c2: u8 = 6;
var pointer = &c1;
try stdout.print("{d}\n", .{pointer.*});
pointer = &c2;
try stdout.print("{d}\n", .{pointer.*});
try stdout.flush();
5
6

一句话理清： - const ptr: *T：指针自身固定（不能换指向），但指向的数据可改； - var ptr: *const T：指针自身可以随时换指向，但指向的数据是只读的。

6.2 指针分类：单项指针与多项指针

在 Zig 规范中，主要有两种指针形态 (Zig Software Foundation 2024)：

  1. 单项指针（Single-item pointer，*T）：明确只指向一个独立的对象。日常写业务绝大多数都是它。
  2. 多项指针（Many-item pointer，[*]T）：星号放在方括号里，指向一块未知长度的连续内存首地址，允许做 C 语言风格的指针算术运算。

6.3 指针算术运算（Pointer Arithmetic）

Zig 同样支持指针算术运算（Pointer Arithmetic），其工作方式与 C 语言一致。当指针指向一个数组时，它起初指向数组的首个元素，你可以通过对指针进行加减偏移来顺序访问数组中的其余元素：

const ar = [_]i32{ 1, 2, 3, 4 };
var ptr: [*]const i32 = &ar;
try stdout.print("{d}\n", .{ptr[0]});
ptr += 1;
try stdout.print("{d}\n", .{ptr[0]});
ptr += 1;
try stdout.print("{d}\n", .{ptr[0]});
try stdout.flush();
1
2
3

尽管你可以像上面这样创建指向数组的指针并通过指针算术遍历数组，但在 Zig 中，我们更推荐使用在 Section 1.6 中介绍过的切片（Slices）。切片在底层本身就是指针，同时还附带了记录元素个数的 len 属性，便于 zig 编译器自动检查潜在的缓冲区溢出等越界问题。此外，你无需使用指针算术，直接通过 slice[index] 语法即可访问任意元素。正如在 Section 1.6 中提到的，只需在方括号中使用范围选择器即可从数组获取切片：

const ar = [_]i32{1,2,3,4};
const sl = ar[0..ar.len];
_ = sl;

6.4 可选类型（Optionals）与告别“十亿美元错误”

在 C 里，任何指针都可能是 NULL，解引用空指针是未定义行为（UB）的常见来源，而且出了问题往往只看到一个含义模糊的段错误（segmentation fault）。所以写 C 的程序员不得不时刻检查指针是不是空的。

而在 Zig 里，所有普通对象和指针默认全部是非空的（Non-nullable）！ 你不需要也不可能在普通类型里藏一个 null。如果你尝试把 null 赋给普通类型，编译器会立即报错拦截：

var number: u8 = 5;
number = null;
p5.zig:5:14: error: expected type 'u8',
        found '@TypeOf(null)'
    number = null;
             ^~~~

普通指针也是同样的规则：在 Zig 里，普通的 *T 指针不可能为 null。所以你可以假设自己创建的指针都指向非空的值，不必再到处检查它是不是 null。

（译注：非空不等于一定有效。指针仍然可能是悬垂指针，比如指向已经释放的堆内存，或者指向已经返回的函数里的局部变量，解引用这类指针同样是未定义行为。）

6.4.1 显式标记可能为空：可选类型 ?T

但在实际业务中，我们难免会遇到“某个值可能存在、也可能不存在（为空）”的合理需求。 这时候就要用到可选类型（Optionals）。Zig 中的可选对象非常类似于 C++ 中的 std::optional 对象，它可以包含一个有效值，也可以什么都不包含（即 null）。

在任何类型前面加一个问号 ?，就能把它升级为可选类型：

var num: ?i32 = 5;
num = null; // 合法！因为它是可选类型

6.4.2 可选指针（Optional Pointers）

同理，如果你需要一个在特殊情况下可以为 null 的指针，类型前面同样加问号 ?*T：

var num: i32 = 5;
var ptr: ?*i32 = &num;
ptr = null; // 合法！
num = 6;

细看对比： - ?*i32：可选指针（指针本身可能是 null，如果不为 null 则指向一个实在的 i32）； - *?i32：指向可选值的指针（指针本身绝对不为 null，但它指向的那个槽位里装的可能是 null）。

var num: ?i32 = 5;
// 此时 ptr 类型是 *?i32
const ptr = &num;
_ = ptr;

6.4.3 显式处理 null 的三种方式

当你的 Zig 代码中存在可选对象时，你必须显式处理它可能为 null 的情况（就像使用 try 和 catch 处理错误一样）。主要有以下三种方式：

  • 使用 if 语句（类似 C 语言中的判空检查，并配合 |val| 解包）；
  • 使用 orelse 关键字；
  • 使用 .? 方法直接解包可选值。

方式一：if 语句解包。使用 if 语句时，可以通过一对竖线 |not_null_num| 将可选值解包。如果 num 为 null，if 代码块不会执行；否则 num 会被安全解包到保证非空的 not_null_num 对象中：

const num: ?i32 = 5;
if (num) |not_null_num| {
    try stdout.print("{d}\n", .{not_null_num});
    try stdout.flush();
}
5

方式二：orelse 默认值表达式。orelse 关键字类似于二元运算符：左侧是可能为 null 的可选表达式，右侧是兜底的非空表达式。如果左侧求值非空则使用左侧的值，若左侧为 null 则采用右侧的替代值（下例中 x 为 null，因此采用了替代值 15）：

const x: ?i32 = null;
const dbl = (x orelse 15) * 2;
try stdout.print("{d}\n", .{dbl});
try stdout.flush();
30

方式三：opt.? 解包（等价于 orelse unreachable）。如果在特定上下文中无法给出合理的替代值，且遇到 null 时最合理的处理方式就是直接触发 panic 报错终止，可以使用可选对象的 .? 方法。 本质上，opt.? 等价于 opt orelse unreachable（详见官方文档中的 unreachable 关键字说明1）。当在 Debug 或 ReleaseSafe 模式下编译时，一旦运行时遇到 null 走到 unreachable 分支，程序就会立即触发 panic 并打印错误栈：

const std = @import("std");
fn return_null(n: i32) ?i32 {
    if (n == 5) return null;
    return n;
}

pub fn main(init: std.process.Init) !void {
    var stdout_buffer: [1024]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &stdout_buffer);
    const stdout = &stdout_writer.interface;
    const y: ?i32 = return_null(5);
    try stdout.print("{d}\n", .{y.?});
    try stdout.flush();
}
thread 12767 panic: attempt to use null value
p7.zig:12:34: 0x103419d in main (p7):
    try stdout.print("{d}\n", .{y.?});
                                 ^
