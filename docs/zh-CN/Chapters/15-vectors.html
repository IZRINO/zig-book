17  向量类型与 SIMD 硬件级并行加速

在这章中，咱们来聊聊 Zig 里的向量类型（Vectors）与 SIMD（单指令多数据流）加速。

首先必须给 C++ 同学打一剂预防针：在 Zig 里，@Vector 绝不是 C++ 里充当动态数组的 std::vector！ Zig 里的动态数组叫 std.ArrayList（详见 Section 11.1）。这里的 @Vector 和 SIMD 运算有关，是 Zig 对 SIMD 向量对象的表示。

17.1 到底什么是 SIMD？

SIMD 是 Single Instruction, Multiple Data（单指令多数据流）的英文缩写。 在音视频编辑和图形应用里，到处都有它的身影。SIMD 不是新技术，但在普通台式机上大量使用是比较近的事，早年它只用在“超级计算机”上。如今大多数 CPU（AMD、Intel 等，不论台式机还是笔记本）都支持 SIMD；如果你的 CPU 很老，就有可能不支持。

普通计算是标量（Scalar）模式：如果要给 4 组数字做加法，CPU 必须老老实实执行 4 次独立的加法指令（ADD），一条接一条跑； 而 SIMD 则是向量化并行模式：现代 CPU（Intel/AMD 的 AVX2/AVX-512、Apple/ARM 的 NEON）体内拥有专门的大位宽寄存器（128 位、256 位甚至 512 位）。一条 SIMD 机器指令，就能同时并排完成 4 个（甚至 16 个）数字的加法计算！

如果说前一章的多线程是“找多个工人同时干活”，那 SIMD 就是“一个工人手里拿了一把能同时切 4 根胡萝卜的特制排刀”！

在 Zig 中，当你在向量类型上使用下面这些操作符时，计算会使用 SIMD 完成，所以这些操作符默认都是逐元素、并行地执行：

  • 算术运算：+、-、*、/、@divFloor()、@sqrt()、@ceil()、@log() 等；
  • 位运算：>>、<<、&、|、~ 等；
  • 比较运算：<、>、== 等。

17.2 向量（Vectors）

SIMD 运算通常通过 SIMD 内建函数（SIMD intrinsic）来完成，这只是“执行 SIMD 运算的函数”的一个好听的叫法。这些函数总是作用在一种特殊的对象上，就是“向量”。所以要用 SIMD，就得先创建一个“向量对象”。

向量对象通常是一块固定大小的 128 位（16 字节）空间。所以常见的向量本质上就是一个数组，里面放 2 个 8 字节的值，或者 4 个 4 字节的值，或者 8 个 2 字节的值，等等。不过不同型号的 CPU 可能有不同的 SIMD 扩展（或者说“实现”），提供更大的向量对象（256 位或 512 位），一个向量里就能放更多数据。

在 Zig 里声明向量，使用内置函数 @Vector(len, PrimitiveType)： 第一个入参是向量包含的元素数量，第二个入参是元素的数据类型。向量里只支持基本数据类型（如 u32、f32）。

看下面这个例子：两个向量直接用普通的加号 + 相加。向量上的数学运算默认是逐元素进行的，因为同一个运算（这里是加法）会被转换成一条指令，并行地作用在向量的所有元素上：

const v1 = @Vector(4, u32){4, 12, 37, 9};
const v2 = @Vector(4, u32){10, 22, 5, 12};
const v3 = v1 + v2; // 逐元素相加
try stdout.print("{any}\n", .{v3});
try stdout.flush();
{ 14, 34, 42, 21 }

这就是 SIMD 提升性能的方式：不用写 for 循环一个个元素地累加，SIMD 会同时并行完成这 4 次加法。

所以，@Vector 本质上就是 SIMD 向量对象在 Zig 里的表示。但只有当前 CPU 支持 SIMD 运算时，向量里的元素才会被并行处理。如果 CPU 不支持 SIMD，@Vector 的性能很可能和用 for 循环写的版本差不多。

17.2.1 将普通数组转换为向量

如果手头已经有一段常规的静态数组，可以通过隐式赋值或切片解引用将其一键升级为硬件向量：

const a1 = [4]u32{4, 12, 37, 9};
const v1: @Vector(4, u32) = a1;          // 整体转换
const v2: @Vector(2, u32) = a1[1..3].*; // 截取切片转为 2 元素向量
_ = v1; _ = v2;

注意：只有长度在编译期已知（compile-time known）的数组或切片，才能被转换为向量。向量一般只支持编译期已知的大小，所以如果数组的大小要到运行时才知道，就得先把它复制到一个大小在编译期已知的数组里，再转换成向量。

17.2.2 标量广播填充：@splat()

如果你想创建一个所有元素数值都相同的向量，不需要手动敲一长串重复数字，直接调用内置的 @splat() 进行标量广播：

// 一键生成填满 10 个 16 的向量
const v1: @Vector(10, u32) = @splat(16);
try stdout.print("{any}\n", .{v1});
try stdout.flush();
{ 16, 16, 16, 16, 16, 16, 16, 16, 16, 16 }

17.2.3 注意事项：切勿创建过大的超宽向量！

正如我们在 Section 17.2 中所述，每个向量对象通常是一块 128、256 或 512 位的小空间。 也就是说，向量对象一般都很小。反过来，如果你创建一个非常大的向量（比如大小接近 \(2^{20}\)），编译器往往会崩溃或报错。例如编译下面这个程序，很可能会在构建过程中遇到段错误或 LLVM 报错：

const v1: @Vector(1000000, u32) = @splat(16);
_ = v1;
Segmentation fault (core dumped)

所以要小心，不要创建太大的向量对象。
